## 1. 一句话目标

给用户一个自助工作台：**自己传背景图 + 角色图，套用预制卡框/卡背，可选自动抠图，实时得到一张可拖动视差、可翻面的全息闪卡**。
把现有 holo-card 流水线里"AI 拆层"这一步交给用户 + 浏览器端抠图模型，其余（合成、视差、全息箔、翻面）全部复用。

## 2. 与现有仓库的关系

- 独立页面 `playground/`，**不触碰首页红线**（首页零 canvas / 零 iframe / 零动画循环），首页只加一个静态入口。
- 合成与交互复用现有 renderer（metalgreymon 的 `job/renderer.js`：视差 + 全息箔 + 翻面），PlayGround 页面随便用 canvas/worker。
- 产出物（P1）可走 AGENTS.md 的落位流程进卡册，形成"玩 → 收录"闭环。

## 3. 用户流程

1. 传**背景图**（建议 2:3，自动压到长边 2048）
2. 传**角色图**（透明 PNG 直用；普通 JPG/PNG 走自动抠图）
3. 选**卡框 / 卡背**（预制，v1 复用黑魔导女孩版式做留空版）
4. 微调：每层缩放/偏移；抠图开关；边缘羽化
5. 预览：拖动视差、点击/按键翻面看卡背
6. （P1）导出 zip，落位成卡册新卡

## 5. 图层合成模型

| z | 层 | 来源 | 说明 |
|---|---|---|---|
| 0 | background | 用户上传 | 卡内窗口的底图 |
| 1 | character | 用户上传（抠图后带 alpha） | 视差位移最大的一层 |
| 2 | ui（卡框） | 预制 | 顶部覆盖，窗口外不透明 |
| 3 | holo foil | CSS 变量 `--foil` | 全站签名渐变，复用 |
| 翻面 | back | 预制卡背 | 与正式卡同机制 |

## 6. 抠图方案对比（关键决策）

| 方案 | 依赖 | 体积 | 质量 | 隐私 | 结论 |
|---|---|---|---|---|---|
| **A. 浏览器端推理**（RMBG-1.4 / isnet，transformers.js 或 @imgly/background-removal） | 零服务端 | 首次下载 ~40–80MB，浏览器缓存 | 通用人物/物体良好 | 全本地 | ✅ P0 推荐 |
| B. 不抠图直显 | 零 | 0 | 取决于用户素材 | — | ✅ P0 必备开关 |
| C. 服务端 rembg | 需起服务 | — | 稳定 | 图片出本地 | ❌ 违背仓库"零构建零服务"，不做 |

**A 方案已拍板：量化版 ~40MB**（RMBG-1.4 INT8，transformers.js）。

**实现细节**：
- 推理前把图缩到长边 ≤1024，跑完 mask 再放大回原尺寸合成（省内存、省时间）。
- 放 Web Worker 跑，主线程只管预览。
- 模型文件首次加载给明确进度条 + "已缓存，下次秒开"提示。
- 抠完给黑白底对照小图自查，残留可切回"不抠图直显"。

## 7. 文件结构

```
playground/
├── index.html          # 工作台单页
├── playground.js
├── renderer.js         # M2 接入 metalgreymon WebGL shader 作"高配渲染"开关
├── frames/             # 卡框/卡背管理目录：往里丢素材 + 在 frames.js 注册即可
│   ├── frames.js       # 预制件注册表（用 <script> 引入，file:// 下可用的 manifest）
│   ├── back-default.webp
│   ├── darkmagiciangirl/{ui.webp, back.webp}
│   ├── metalgreymon/ui.webp
│   └── tailmon/ui.webp
├── presets/            # 预制素材库（v0.2 新增，v0.3 加卡背），注册表同 frames.js 模式
│   ├── presets.js
│   ├── backgrounds/    # 4 套，复用 holo-card 各卡 background.webp
│   ├── characters/     # 4 套，复用 holo-card 各卡 character.webp（含 alpha）
│   └── backs/          # 3 套卡背：经典 + HSV 变色两套（翠沼/紫霞）
```

用户素材不落盘（P0 内存 + P2 IndexedDB 草稿）。

**渲染策略（v0.4 更新）**：预览已切换为 **WebGL shader 渲染**——`playground/renderer.js` 复用 metalgreymon 渲染器快照，新增三组 uniforms（`charScale`/`charOff`/`bgScale`）承接层微调滑杆；合成前把三层统一到"角色 alpha 包围盒"尺寸（bg cover、frame fill），结构线（轮廓辉光）用角色 alpha 的 Sobel 边缘实时生成，用户素材无需预做 structure.webp。

## 8. 首页接入（已提前完成）

- hero 卡区「随机」旁加 **PLAYGROUND 全息箔胶囊入口**（`<a>` 静态链接，复用 `.shuffle-btn` 样式 + 星光图标）。
- 不进收录架 grid：计数徽标由 JS 按 `.mini-card` DOM 统计，混入会让 DEMO 计数虚高，违背"诚实计数"。
- `heroCards` 数组不动；导出落位的卡再走正常收录流程。

## 9. 风险与边界

| 风险 | 对策 |
|---|---|
| 模型首次 40MB+ 下载 | 进度提示 + 浏览器缓存；加载前先让用户玩"直显模式" |
| 大图内存爆 | 上传即压长边 2048；推理再压 1024 |
| iOS HEIC | 仅接受 png/jpg/webp，其余给格式提示 |
| 抠图质量翻车 | 开关可关 + 黑白底自查 + 层微调兜底 |
| 版权 | 页面注明仅供个人 demo；沿用 THIRD_PARTY_NOTICES 习惯 |
